# 拾序：預約服務需求評估 POC

這是一個在本機執行的概念驗證，讓潛在客戶用自然語言說明預約需求，再逐步整理成服務功能、規則、待確認事項與示範費用，最後可留下聯絡資料供人工跟進。

目前版本驗證的是「預約服務需求評估」流程。較早期的對話曾討論設計接案與品牌報價，那是過往探索紀錄，不是現在程式的功能或需求規格。這個 POC 不會真的建立預約行事曆、收款、寄信或自動聯絡客戶。

## 快速開始

需求：Node.js 24 以上、Codex CLI，以及可用的網路連線。

```sh
npm ci
codex login
npm start
```

用瀏覽器開啟 `http://localhost:3000`。Codex CLI 必須由使用者本人登入；朋友下載後請用自己的 Codex 帳號登入，不要共用或複製任何人的登入資料。這個 POC 透過 Codex CLI 使用已登入的 ChatGPT 訂閱，不需要設定 API key。

預設服務綁定 `0.0.0.0:3000`，同一區域網路的裝置也能連到這台電腦。只想在本機使用時，可啟動為：

```sh
HOST=127.0.0.1 npm start
```

可用 `PORT` 更改連接埠；`CODEX_MODEL`、`CODEX_EFFORT` 與 `CODEX_TIMEOUT_MS` 可調整模型、推理程度與逾時秒數。預設為 `gpt-6-luna`、`low`、30 秒。

## 流程與資料

1. 使用者描述希望客戶如何預約，以及現有安排方式。
2. 模型將對話整理為固定欄位，讓使用者確認理解是否正確。
3. 介面逐步追問尚未提供的資訊；使用者可先看結果，再返回補充。
4. 程式依示範價目計算月費與設定費，未決或額外開發項目列為待評估。
5. 使用者可儲存姓名與 Email／電話，供人工後續聯絡；目前沒有名單管理頁。

模型處理的欄位包括服務功能、使用目的、人員、時段與規則、目前流程與整合、預算、開始日期。模型服務需要網路；輸入的需求文字會送至模型服務處理。程式不會把聯絡表單送給模型。

工作階段資料以 JSON 保存在 `data/appointment-sessions/`。其中可能有需求原文、模型整理結果及聯絡資料；請勿將該目錄、真實使用者資料或執行紀錄提交到 GitHub。`data/`、環境變數檔與日誌已列入 `.gitignore`。舊版設計接待資料留在 `data/sessions/`，程式不會自動轉換或混用。

費用僅來自 `config/pricing.json` 的 POC 示範價目，並非市場行情或正式報價。此版本沒有實作正式服務、付款、稅額、折扣或第三方服務串接。

## 開發與檢查

```sh
npm test
npm run benchmark
```

`npm test` 使用內建 Node.js 測試執行程式與 HTTP 測試。`npm run benchmark` 會呼叫已登入的 Codex CLI，以合成案例進行真實模型評估；需要有效登入與網路，會消耗模型使用額度。`npm run replay -- <JSON檔路徑>` 可重播一份指定的本機工作階段；請勿將真實工作階段檔分享或提交。

程式入口是 `server.js`；需求整理提示與模型呼叫在 `lib/compiler.js`，欄位整理、追問與費用計算在 `lib/domain.js`，介面在 `public/`，示範價目在 `config/pricing.json`，合成案例與測試在 `fixtures/`、`tests/`。
