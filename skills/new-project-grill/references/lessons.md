# 可重用經驗及適用情境

此 Skill 由使用者提供的九張 QA 工作流程照片、四個新專案相關對話、ChatGPT 研究稿及實際 POC 經驗提煉。未取得照片中的 qa-ticket-grill 原始 Skill，照片未展示完整題庫與經驗清單；本套件是方法重建，不是原檔逐行移植。來源私人對話及照片不附在套件中。

| 經驗 | 適用情境與處理 |
|---|---|
| 新手說不清技術名稱 | 用具體工作與例子澄清，再由 Agent 查術語與選型；不把自己的猜測當成確認。 |
| 問到發散、使用者不耐煩 | 整理已知、讓可委託的細節代選、先交可 review 計畫；保留真正必要的問題。 |
| 現況已有成熟成果 | 先查到哪裡、讀來源並找可沿用部分，再裁切到本次用途。 |
| 本機服務仍可能用雲端 | 分清前端、後端、模型／其他服務與資料路徑。 |
| 登入成功不是介接成功 | 必要時用最小真實呼叫確認輸出及耗時；現有版本可用也不是朋友的機器已驗證。 |
| 架構依驗證目標裁切 | POC 可先處理文字或單一流程；不把研究稿所有元件搬進首版。 |
| 示範服務不等於已實作 | 例如費用評估頁列出預約功能，不代表真正有預約行事曆或通知；交付要明示。 |
| 使用者會改口、想提早看結果 | 保留未知與否定，允許返回補充及修訂；不要丟掉草稿或不相關決策。 |
| 固定案例有助比較 | 隨問題累積合成／允許的案例，記版本與實測；只報當次測量，避免泛化成保證。 |
| 原文來源比模型重述可靠 | 需要可追溯證據時保留原始來源或引用位置；不可把推論或生成內容寫成原話。 |
| 交接位置可能不同於開發位置 | 檢查朋友實際取得的版本與啟動方式；README、現行規格、舊討論分開標示。 |
| 取得／安裝／啟用是不同狀態 | 交付依任務驗證真正可用，缺少某一步就明列。 |

這些案例不固定 Node.js、模型、價格、日文回報、公司工具、不准 push 或不讀所有環境設定等規則。當次資料與當地規則決定適用範圍，不保存記憶、不帶出私人來源。
